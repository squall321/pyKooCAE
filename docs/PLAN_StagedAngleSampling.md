# 전각도 낙하 단계별(Staged) 샘플링

작성일 2026-08-02 · 요청자 박국진

## 1. 목적

전각도 낙하를 **작은 규모로 먼저 돌리고 나중에 채워 넣는** 워크플로우를 지원한다.
단계 수를 `120 → 500 → 1000` 처럼 정해 두면, 어느 단계에서 시작하든 **누적 위치 셋이 항상 동일**해야 한다.

## 2. 현재 구조와 한계

`AngleSourceParser.parse_fibonacci_lattice` 는 N 개 점을 생성한다.
`sampling_space="physical"` 이면 `_physical_lattice` 가 실제 낙하방향 공간에서 등간격 배치한다.

실측(2026-08-02)으로 확인한 한계.

```
progressive=False : 120세트 ∩ 500세트 = 0/120
progressive=True  : 120세트 ∩ 500세트 = 0/120
1000세트의 앞 500개 == 500세트 : False
같은 설정 2회 실행 → 완전 동일 (결정론은 성립)
```

후보풀이 `max(4N, 64)` 로 N 에 묶여 있어 **N 이 바뀌면 점 위치가 통째로 달라진다.**
따라서 "500 을 돌린 뒤 1000 으로 확장" 이 불가능하고, 500 을 버리고 1000 을 새로 돌려야 했다.

## 3. 설계 — 이전 단계 선언 + 최근접 제거

각 단계 생성이 결정론적이라는 점을 이용한다. **이전 단계 목록만 선언하면** 이전 위치를
그대로 재현할 수 있으므로, 누적 결과도 항상 동일해진다.

```
previous_stages = [120, 500],  num_points = 1000

1) 이전 누적 재현
   acc = gen(120)                                   # 120개
   acc += remove_nearest(gen(500),  acc, 120)       # +380 → 500개
2) 이번 단계
   new  = remove_nearest(gen(1000), acc, 500)       # 500개
3) 방출 = new (500개).  누적 = 1000개
```

`remove_nearest(cands, prev, k)` 는 `prev` 각 점이 가장 가까운 미제거 후보를 하나씩
가져가 정확히 `k` 개를 제거한다. 거리는 **실제 낙하방향(`_physical_drop_dir`) 사이 각거리**로
잰다(파라미터 공간이 아니라 물리 공간이 의미 있는 척도이므로).

### 개수 규약

`num_points` 는 **최종 누적 총량**이다. 방출 개수 = `num_points - previous_stages[-1]`.
(사용자 확정: "총 500 (신규 380)")

### 이름

방출 점 이름은 누적 순번을 잇는다. `previous_stages=[120,500]`, `num_points=1000`
→ `P0501` ~ `P1000`. 단계가 달라도 같은 물리 위치는 같은 번호를 갖는다.

## 4. 품질 실측 (2026-08-02)

| 구성 | 최소간격 min | 중앙 | 뭉침(정규 min 의 절반 미만) | 중복(0.1° 이내) |
|---|---|---|---|---|
| 누적 500 (120→500) | 4.59° | 7.66° | 0개 | 0개 |
| 정규 500 | 7.93° | 8.68° | — | — |
| 누적 1000 (120→500→1000) | 3.15° | 4.73° | 0개 | 0개 |
| 정규 1000 | 5.60° | 6.10° | — | — |

**대가**: 최악 간격이 정규 대비 약 56% 로 줄어든다. 서로 다른 격자를 겹치는 데서 오는
불가피한 손실이다. 다만 심한 뭉침과 중복은 0 이고 중앙값은 거의 유지되므로 실용상 문제없다.
정규 격자 수준의 균일도가 꼭 필요하면 단계를 쓰지 말고 목표 N 을 한 번에 돌려야 한다.

## 5. 제거 알고리즘 선택

두 방식이 같은 결과를 냈다(누적 500 기준 둘 다 min 4.59° / 중앙 7.66°).

- 전역 그리디: 모든 (prev, cand) 쌍 정렬. O(P·N log) 시간, **O(P·N) 메모리** → 큰 N 에서 불가
- **prev별 최근접(채택)**: prev 순서대로 각자 최근접 미제거 후보 제거. O(P·N) 시간, **O(N) 메모리**

품질이 같으므로 단순하고 메모리가 선형인 후자를 쓴다.

## 6. 변경 범위 (가산 3-hunk)

1. `Runner/AngleSourceParser.py`
   - `FibonacciLatticeConfig.previous_stages: Optional[List[int]] = None`
   - `_physical_drop_dir` 기반 `_angular_remove_nearest()` 헬퍼
   - `parse_fibonacci_lattice` 에 staged early-branch
2. `Runner/CumulativeDesigner.py` — `_parse_angle_source` 에서 `previous_stages` 읽기
3. 검증 스크립트/회귀

## 7. 불변식

- `previous_stages` 미설정 시 **기존 동작 바이트 동일** (회귀 0)
- `previous_stages` 는 오름차순·양수·전부 `num_points` 미만
- 방출 개수 == `num_points - previous_stages[-1]`
- 누적 셋에 중복(0.1° 이내) 0 개
- 같은 설정 2회 → 완전 동일

## 8. 미포함

- `latlon` 공간에서의 단계 사용은 허용하되 권장하지 않음(물리 공간 쏠림). 거리 자체는
  두 공간 모두 물리 방향으로 계산한다.
- 단계 간에 `progressive` / `principal_directions` 가 바뀌면 이전 위치 재현이 깨진다.
  **모든 단계가 같은 설정이어야 한다**(num_points 만 다름). 검증에서 막지 못하므로 문서로 경고.
