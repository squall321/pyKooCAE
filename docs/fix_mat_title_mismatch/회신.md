# 회신 — `*MAT_VISCOELASTIC_TITLE` 파괴 신고 (2026-09-29)

결론부터. **증상은 정확했고 원인 가설 2건은 사실과 다릅니다.** 원인을 재현으로 확정하고
무언 손실을 차단했습니다. 우회법(`_TITLE` 떼고 쓰기)은 지금도 유효하지만 이제 불필요합니다.

## 1. 실제 원인 — 입력 덱이 "bare 키워드 + 제목 줄"

```
*MAT_VISCOELASTIC          ← _TITLE 이 아닌데
Epoxy_100M                 ← 제목 줄이 남아 있다
$#     mid        ro ...
        151.30000E-9 ...
```

이 형태를 최소덱으로 재현하니 신고 증상과 글자 단위로 일치했습니다.

```
mid=47  name=Viscoelastic47  K=66.57   ← 정상
mid=48  name=Viscoelastic0   K=0.0 G0=0.0 GI=0.0 BETA=0.0
mid 15 존재: False
```

**무언 손실 4단계**

1. bare 분기가 제목 줄을 카드1 로 읽음 → `KooDynaInt("Epoxy_100M")` = **0**, 실수 전 필드 0
2. `name = "Viscoelastic{0}".format(0)` → `Viscoelastic0`
3. `AddMaterial` 의 `if material.id == 0: material.id = self.maxid + 1` → **조용히 재부여**
   (귀사 로그의 **701** 은 그 모델의 `maxid` 가 700이었다는 뜻입니다. 제 최소덱은 48이 됐습니다)
4. 원래 MID 미등록 → 참조 파트 전원 고아 → `Error 10157` × 참조 파트 수, `Error 10293`(G0==GI==0)

## 2. 원인 가설 정정 2건

**① `_TITLE` 분기는 이미 있습니다** — `KooMaterial.py:1485`. 정상 동작합니다.
제목 + `$#` 주석 + 데이터 구성을 정확히 복원합니다
(`mid=15 name=Epoxy_100M rho=1.3e-09 K=64.444 G0=48.333 GI=15.104 BETA=2500.0`).
요청 #1(분기 추가)은 불필요했습니다. 그대로 했다면 **없는 문제를 고치고 진짜 원인은 남았을** 것입니다.

**② 런마다 갈리는 게 아니라 덱마다 갈립니다.** 경쟁 조건도 캐시도 아닙니다. 같은 덱이면
결정적으로 같은 결과입니다. 8런 중 6/2 로 갈린 것은 **덱이 달랐다**는 뜻입니다.
현재 덱(2728행)은 `_TITLE` 로 올바르니, 실패한 6런은 그 이전 버전 덱을 썼을 가능성이 큽니다.
`mkmat15.py` 를 캠페인 중에 수정하셨다면 정확히 이 그림이 됩니다.

확인 방법 — 각 Run 의 입력 덱 해시를 덱 파일과 대조하십시오.
```bash
md5sum /data2/T4MAT/decks/H4_VE.k
for r in /data2/T4MAT/MAT_H4_VE/output/Run_*; do
  printf "%s  " "$(basename $r)"
  grep -A3 '^\*MAT_VISCOELASTIC' $r/DropSet.k | grep -m1 -E 'Viscoelastic0|Epoxy_100M'
done
```

## 3. 조치

**요청 #2 는 문자 그대로 하지 않았습니다.** "`AddMaterial` 의 id 0 무언 재부여 제거" 가
요청이었으나, `KooMaterial.py:1104~1125` 의 팩토리 5곳이 `id=0` 을 넘겨 자동부여를 **의도적으로**
씁니다(바닥판·충격추 재질). 그대로 하면 DROP_ATTITUDE 가 전량 깨집니다.
→ `AddMaterial` 은 불변, **파싱 시점**에서 막았습니다. 그 자리에서 MID 비숫자는 파싱 실패밖에
될 수 없고 자동부여 경로는 여기를 지나지 않습니다.

| 요청 | 조치 |
|---|---|
| #1 `_TITLE` 분기 추가 | 불필요 — 이미 있음 |
| #2 재질 수 불변 검증 | `_ReportMaterialMIDInvariant` — 입력 덱 MID 집합 vs 등록 집합 대조. 파트가 참조하는 소실은 🔴, 미참조 소실은 Info. **중단은 안 합니다** (`MAT_GENERAL_VISCOELASTIC` 등 의도적 raw 보존을 깨뜨리므로) |
| #3 파싱 실패 시 원문 포함 | 에러에 키워드·문제 줄 원문·MID 필드·진단·조치 포함. 줄번호는 이 계층에 정보가 없어 미포함 — 원문으로 grep 가능합니다 |
| #4 MID 0 즉시 에러 | `_GuardMaterialMID` — MID 필드가 비숫자면 즉시 중단 |

에러 메시지 실물.

```
ValueError: 재질 카드의 MID 필드가 숫자가 아니다 - 키워드와 내용이 맞지 않는다.
  키워드   : *MAT_VISCOELASTIC
  읽은 줄  : 'Epoxy_100M'
  MID 필드 : 'Epoxy_100M'
  진단     : 이 줄은 제목(title)으로 보인다. 키워드에 _TITLE 이 없으면
             LS-DYNA 도 이 줄을 카드1 로 읽어 실패한다.
  조치     : 키워드를 *MAT_VISCOELASTIC_TITLE 로 바꾸거나, 제목 줄을 지울 것.
  참고     : 예전에는 이 상태가 조용히 통과해 MID 가 0 으로 읽히고
             maxid+1 로 재부여되어 원래 MID 가 사라졌다.
```

MID 판정은 **선언 근거**로 했습니다 — LS-DYNA 규격상 `*MAT_*` 카드1 필드1 은 정수 MID 입니다.
`KooDynaInt` 반환값이 0인지로 보지 않습니다(0 은 정상 값일 수도 있고, 실수표기 `2.0` 을
정수로 복원하도록 이미 수정된 이력이 있습니다). 자유간격 콤마와 지수표기 `eE` 는 허용합니다.

## 4. 회귀 증명

- DROP `DropSet.k` **바이트 동일** (동일 옵션파일로 변경 전/후 생성해 md5 대조).
  `DropSet.json` 은 `run_id` 한 필드만 다르고 산출물 구성 동일
- 실제 덱 **10개**에서 MID 불변식 오탐 **0** — raw 보존 시험덱 포함
- 시험 6종 전부 통과. 신규 `tests/test_mat_title_mismatch.py` 16항목

## 5. 우회법 평가

제목 없이 쓰는 우회법은 맞습니다(`mid 47·48` 형식). 다만 **제목을 유지해도 정상 동작**하므로
원하시면 `*MAT_VISCOELASTIC_TITLE` 로 되돌려도 됩니다. 중요한 것은 **키워드와 내용을 맞추는 것**
하나입니다. `mkmat15.py` 가 둘 중 어느 형식을 내든 일관되게만 내면 됩니다.

검증 명령은 그대로 유효하고, 이제 전처리 단계에서 먼저 걸립니다.
```bash
grep -A2 '^\*MAT_VISCOELASTIC' <Run>/DropSet.k | grep -c 'Viscoelastic0'   # 0 이어야 한다
```
