명령어 1/6

prepare — 설정 파일 생성

사용자가 작성한 scenario.json을 실행 가능한 runner_config.json으로 변환합니다.
DOE 각도/위치 계산, 디렉토리 생성, 헬퍼 스크립트 자동 생성까지 한 번에 처리합니다.

KooChainRun prepare scenario.json
KooChainRun prepare scenario.json -o ./config.json

생성 결과물

  • 📄 runner_config.json — 상세 실행 설정
  • 📁 output/slurm_scripts/ — 사전 생성
  • 🔧 rerun.sh / stop.sh
  • 🔧 diagnose.sh / copy.sh
  • 🔧 copylog.sh / clean.sh
  • 🔧 kill_dyna.sh

명령어 2/6

submit — Slurm 잡 제출

DOE별 sbatch 스크립트를 생성하고 Slurm에 제출합니다. 노드 헬스체크, 시간 제한 검증, 순차/병렬 모드를 지원합니다.

# 기본 (DOE당 1잡, 4노드 × 1잡)
KooChainRun submit runner_config.json \
  --nodes 4 --partition normal

# sequential 모드 (노드당 배치잡)
KooChainRun submit runner_config.json \
  --nodes 4 --sequential

자동 처리 항목

  • 🔍 Node Health Check — SSH parallel ping
  • 🚫 Dead node 자동 제외 (--exclude)
  • ⏱️ Partition 시간 제한 자동 cap
  • 🔒 --exclusive 노드 독점 (기본)
  • ⏳ Job stagger (기본 300초, NFS 충돌 방지)
  • 📝 jobs.json 즉시 생성

Scratch 모드 (성능 최적화)

NFS 대신 로컬 scratch에서 연산 → 완료 시 NFS 동기화

# scenario.json environment 설정
"scratch_run": {
  "enabled": true,
  "scratch_base": "/tmp",
  "cleanup_on_success": true
}

--sequential 모드

N개 노드에 DOE를 균등 분배.
노드당 1개 Slurm 잡, 내부에서 M개 DOE 순차 실행.
대규모 DOE에서 잡 제출 오버헤드 최소화.

명령어 3/6

run — 단일 DOE 실행 (계산 노드)

Slurm이 계산 노드에서 자동 호출합니다. KooMeshModifier → LS-DYNA → dynain 전달까지 누적 파이프라인을 실행합니다.

# Slurm 스크립트 내부에서 자동 호출
KooChainRun run runner_config.json \
  --doe 42

# 중단 지점에서 재개
KooChainRun run runner_config.json \
  --doe 42 --resume

# Batch KooMeshModifier 모드
KooChainRun run runner_config.json \
  --doe 42 --skip-koomeshmodifier \
  --pregenerated-dir ./pregenerated

NFS 안정성 보호

  • 🔒 simulation_index flock (120초 타임아웃)
  • 📖 lock 후 재읽기 + merge (double-check)
  • 💀 stale lock 자동 회수 (dead node 대응)
  • 🧹 Apptainer orphan 프로세스 정리

DOE별 파이프라인

Step 1 KooMeshModifier — DropSet.k 생성
↓
Step 2 LS-DYNA (Apptainer) — 해석 실행
↓
Step 3 dynain 추출 → 다음 스텝 입력
↓ (다단계 반복)
완료 simulation_index 업데이트

Checkpoint 시스템

checkpoint_doe_N.json으로 각 스텝 상태 저장.
중단 후 --resume으로 마지막 완료 스텝부터 재개.

명령어 4/6

status — 진행 현황 모니터링

모든 DOE의 완료/실행중/실패/미시작 상태를 실시간으로 확인합니다.

KooChainRun status
KooChainRun status runner_config.json
KooChainRun status --watch   # 60초마다 자동 갱신

DOE 상태 분류

상태설명
completed모든 스텝 성공 완료
running현재 Slurm RUNNING/PENDING
failed스텝 실패 (로그 에러 감지)
killedCANCELLED / TIMEOUT / NODE_FAIL
license_errorLSTC 라이선스 체크아웃 실패
not_started잡 미제출 또는 대기

상태 판단 로직

  • simulation_index에서 DOE별 스텝 alias 조회
  • 중간 스텝: dynain 파일 존재 확인 (다음 스텝 입력 보장)
  • 마지막 스텝: index status="completed" 직접 신뢰
  • sacct / squeue로 Slurm 상태 cross-check
  • 손상 JSON 감지 시 별도 경고 출력

출력 예시

완료: 156/200개
실행중: 12개 (DOE 031~042...)
실패: 3개
미시작: 29개
─────────────────────────────
DOE  001: ✅ completed  (1/1)
DOE  002: 🔄 running   (0/1)
DOE  003: ❌ failed    (0/1)
명령어 5/6

rerun — 실패/미완료 DOE 재실행

완료된 DOE는 건너뛰고 실패·미시작 DOE만 식별하여 재제출합니다. 노드 장애, 타임아웃, 취소 등 다양한 상황에 대응합니다.

# 기본 재실행 (확인 후 제출)
./rerun.sh

# 상태 미리 보기만 (dry-run)
./rerun.sh --dry-run

# 확인 없이 즉시 재실행
./rerun.sh --force

# 특정 DOE만 재실행
./rerun.sh --does 3,7,15,42

# 실패 노드 자동 제외
./rerun.sh --exclude-nodes auto

# sequential 배치 모드 + stale 정리
./rerun.sh --sequential --nodes 4 \
            --cleanup-stale

--exclude-nodes auto

sacct에서 NODE_FAIL / TIMEOUT / FAILED 상태 잡의 노드를 자동 감지.
CANCELLED(사용자 취소)는 제외하지 않음 — 건강한 노드에서 재실행 가능.

--sequential + --nodes

남은 DOE를 N개 노드에 균등 분배.
노드당 1개 Slurm 잡으로 여러 DOE 순차 처리.
소수 노드에서 대량 DOE 재실행에 적합.

--cleanup-stale

재실행 전 이전 중단 DOE의 Run 디렉토리 삭제.
불완전한 결과 파일이 혼입되지 않도록 보장.

명령어 6/6

stop  /  diagnose

실행 중인 모든 잡을 안전하게 취소하거나, 실패 원인을 자동 진단합니다.

stop
# 모든 잡 취소 + LS-DYNA 프로세스 강제 종료
./stop.sh

# 도움말 (취소 없이 옵션 확인)
./stop.sh --help

stop 동작

  • jobs.json에서 전체 job_id 조회
  • 미완료 잡 scancel 실행
  • kill_dyna.sh 호출: 계산 노드 SSH 접속 후
    lsdyna / mpirun / squashfuse 프로세스 강제 종료
  • --help는 실제 취소 없이 도움말만 출력
diagnose
./diagnose.sh
KooChainRun diagnose ./test_dir/

diagnose 감지 항목

원인 코드감지 방법
license_error로그에서 LSTC_FILE / Cannot connect 패턴
disk_full로그에서 No space left 패턴
out_of_memory로그에서 out of memory / oom 패턴
apptainer_errorsquashfuse / libfuse 패턴
cancelledSlurm state = CANCELLED
slurm_timeoutSlurm state = TIMEOUT
not_started잡 미제출 / 상태 없음
헬퍼 스크립트

자동 생성 Helper Scripts

prepare 실행 시 테스트 디렉토리에 자동 생성됩니다. 모두 --help 옵션을 지원합니다.

./rerun.sh

실패/미완료 DOE 재실행. KooChainRun rerun의 단축 래퍼.
모든 rerun 옵션 pass-through 지원.

./stop.sh

모든 Slurm 잡 취소 + kill_dyna.sh 호출.
--help 시 실제 취소 없이 도움말만 출력.

./diagnose.sh

실패 DOE 원인 자동 진단.
라이선스 / 디스크 / OOM / Apptainer 에러 분류.

./copy.sh

로컬 scratch → NFS Output 동기화.
--all: 전체 scratch 복사
N: 병렬 스레드 수 지정 (기본 5)

./copylog.sh

계산 노드에서 로그 파일만 선택 복사.
실행 중 실시간 로그 모니터링에 사용.

./kill_dyna.sh

이 프로젝트의 모든 계산 노드에 SSH 접속하여
lsdyna / mpirun / squashfuse 프로세스 강제 종료.

📌 안전한 --help 보장

이전 버전의 stop.sh --help가 실제로 잡을 취소하는 버그 수정 완료.
모든 헬퍼 스크립트는 --help / -h 감지 시 실제 동작 없이 도움말만 출력합니다.

DOE 설계

낙하 방향 DOE 자동 생성

다양한 낙하 방향을 수학적으로 균등 분포시켜 커버리지를 최대화합니다.

Fibonacci Lattice (권장)

구면 상의 N개 방향을 최대 균등 분포로 생성.
소수 황금각(137.5°) 기반 나선 배치.

"angle_source": {
  "source_type": "fibonacci_lattice",
  "fibonacci_lattice": {
    "num_directions": 200
  }
}

균등 그리드

roll/pitch/yaw 범위와 스텝 수로 격자 정의.

"angle_source": {
  "source_type": "uniform_grid",
  "uniform_grid": {
    "roll": [0, 360, 10],
    "pitch": [-90, 90, 10]
  }
}

누적 해석 (Cumulative)

1개 DOE = N번 연속 해석.
각 스텝의 결과(dynain)가 다음 스텝의 초기 상태가 됩니다.

"cumulative": {
  "num_steps": 3,
  "mode_sequence": [
    "DROP",
    "BOUNCE",
    "SLIDE"
  ],
  "angle_mixing": {
    "strategy": "same_angle"
    // 또는 "random_angle"
  }
}

Alias 체계

각 해석 결과의 고유 식별자:
{Project}_CUM{steps:03d}_DOE{doe:03d}_S{step:03d}_{mode}_{condition}

예: HWDrop_CUM003_DOE042_S001_DROP_P0042

신뢰성

안정성 & 내결함성 기능

실제 운영 환경에서 발견된 문제들을 해결하는 안전 메커니즘들입니다.

🔒

NFS flock 직렬화

simulation_index.json 동시 쓰기 충돌 방지.
120초 타임아웃 + stale lock(dead node) 자동 회수.
lock 해제 후 파일 재읽기 + merge로 데이터 손실 방지.

💀

Dead Node 자동 감지

submit 시 SSH parallel ping으로 응답 불가 노드 사전 감지.
--exclude로 자동 제외하여 "launch failed requeued held" 방지.

⚡

Job Stagger

여러 잡이 동시에 완료되어 NFS에 폭발적으로 쓰기 요청하는 것을 방지.
잡 시작 시 최대 300초 랜덤 지연 (설정 가능).

🧹

Apptainer 정리

잡 시작 전 orphan squashfuse 프로세스 자동 정리.
stale .lock 파일 (10분 이상) 자동 삭제.

📝

Atomic JSON Write

jobs.json / simulation_index.json 모두
임시파일 쓰기 → rename 방식으로 저장.
중단 시 파일 손상 완전 방지. 백업 파일 자동 유지.

🏥

노드 상태 점검 (잡 내)

각 잡 시작 시 출력 디렉토리 쓰기 테스트.
readonly / NFS 장애 노드는 즉시 exit 1로 탈출.
정상 노드에서 자동 requeue.

Quick Start

5단계로 시작하기

처음부터 결과 수집까지 전체 흐름입니다.

1   설정 준비

# scenario.json 작성 후
KooChainRun prepare scenario.json
# → runner_config.json + 헬퍼 스크립트 생성

2   잡 제출

KooChainRun submit runner_config.json \
  --nodes 4
# → jobs.json 생성, Slurm에 제출

3   진행 확인

KooChainRun status --watch
# 또는 squeue -u $USER
# 완료: N/200개

4   실패 재실행

./diagnose.sh   # 원인 파악
./rerun.sh --exclude-nodes auto
# 실패 노드 제외하고 재실행

5   결과 수집

KooChainRun collect runner_config.json ./results/
# 또는 copy.sh로 scratch → NFS 동기화
./copy.sh
빌드 & 배포

빌드 및 배포 시스템

Nuitka로 컴파일하여 단일 바이너리로 배포합니다. Python 미설치 환경에서도 실행 가능합니다.

# 빌드 (Python 3.12 기준)
bash build_KooChainRun_python312.sh

# 결과물
build_dist/bin/KooChainRun   ← symlink
build_dist/lib/KooChainRun/
  KooChainRun.bin            ← Nuitka 바이너리
  *.so                       ← 공유 라이브러리

# 자동 설치 (빌드 스크립트 내부)
/opt/SmartTwinPreprocessor/
/data/SmartTwinPreprocessor/

배포 경로

  • 개발: /opt/SmartTwinPreprocessor/
  • 운영: /data/SmartTwinPreprocessor/
  • scenario.json의 koochainrun_path로 참조

주의사항

  • Python 소스 파일은 직접 복사 불가
    → Nuitka 빌드 필요 (바이너리에 번들)
  • Runner/ 모듈 변경 후 반드시 재빌드
  • squashfuse 필요: apt install libfuse2

Apptainer 환경 주의

  • APPTAINER_TMPDIR은 호스트 환경변수로 설정
    (os.environ, --env 아님)
  • LSTC_LICENSE_SERVER는 헤드노드 IP
    (localhost는 계산 노드 → signal 12 오류)

Apptainer 설정 (scenario.json)

"lsdyna_apptainer_env": {
  "LSTC_LICENSE_SERVER": "192.168.122.1",
  "FI_PROVIDER": "tcp",
  "I_MPI_FABRICS": "ofi"
}
