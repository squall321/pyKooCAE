# 결정 노트
## g 를 높이 값이 아니라 재질 밀도로 판정하는 이유
높이는 단위와 무관하게 50 mm·0.5 m 가 둘 다 흔해 값으로 가를 수 없다. 반면 재질 밀도는 단위계마다
자릿수가 크게 다르다 (강철 ton/mm³ 7.85e-9, kg/m³ 7850). 모델 전체 중앙값이면 폼·강체 몇 개에 흔들리지 않는다.
kg-mm-ms (1e-7~2e-5)·g-mm-ms 는 시간 단위까지 달라 g 를 자동으로 정하지 않고 Gravity 키를 요구한다 (옛 추정 + 경고).
## DWI 는 Gravity 를 명시한다
워크플로우는 이미 mm 를 전제(g=9810)로 속도를 만들었다. 추정에 맡기지 않고 그 전제를 키로 넘겨 결과를 의도와 같게 한다.

## 실모델 신구 g 비교 결과
MinimumModel.k(밀도 중앙값 2.33e-9) h=1500·150 동일, h=100·50 은 9.81→9810 (옛 추정 오류 교정).
Impact_1·MultiscaleTest(2.44e3·2.2e3) h=0.5 동일. 달라지는 건 옛 추정이 틀리던 조합뿐.

## KAM exit 교체는 바이트 단위로
KooAutomatedModeller.py·Component.py·PackageGenerator.py·Capacitor.py·WarpageSolderJoint.py 는 CRLF 다.
텍스트 모드로 읽고 쓰면 파일 전체 줄끝이 LF 로 바뀌어 diff 가 수백 줄이 된다 (한 번 그렇게 했다가 되돌림).

## Evolver: 복사 대신 링크
설치본 Library/Evolver 는 22MB. 호출부는 작업 폴더 Library/Evolver 에 스크립트·STL 을 쓰기만 하므로 실행 파일 링크 하나면 된다.
작업 폴더에 이미 있으면 손대지 않아 기존 사용 방식은 그대로.

## restack 라벨
MID<숫자> 경로는 그대로 두고, 자리표시가 없을 때만 첫 필드를 라벨로 본다. 숫자도 라벨 취급(같은 숫자 = 같은 재질) —
기존 MID 번호를 그대로 쓰는 뜻으로 적었어도 새 번호 카드를 따로 내므로 기존 재질과 충돌하지 않는다.
