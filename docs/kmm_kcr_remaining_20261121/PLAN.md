# 계획 — KMM·KCR 남은 결함 묶음 (2026-11-21)

## 배경
사용자 요청(11-21): 「남은 결함도 모두 해결해. 그리고 우리가 세운 계획중 아직 진행하지 않은것들이 있다면 알려줘」.
기록(docs·메모리·옆 세션 답)에 열린 채 남은 결함을 지금 소스에서 다시 재현해 보고, 재현되는 것을 고친다.
재현하다가 같은 계열의 조용한 소실을 더 찾았다 — 같이 고친다.

## 범위를 정한 기준
- 고친다: ① 지금 소스에서 재현되고 ② 앞선 사용자 결정으로 닫히지 않았고 ③ 바깥 입력(라이선스·다른 저장소·사용자 결정)에 막히지 않은 것.
- 설계 한계는 구현하거나, 적어도 조용하지 않게(🔴 알림·rc) 만들고 보고한다.
- 순서: (가) 조용한 소실·틀린 값 → (나) 올바른 입력에서 죽음 → (다) 나머지.
- KooRemapper 결함은 그 저장소 세션이 맡는다(여기서는 손대지 않는다).
- 기존 해석(DROP·IMPACT·VIB)을 깨지 않는다 — 공유 코드 변경은 말뭉치 대조로 「빠지는 것 0, 바뀐 바이트는 모두 되살아난 값」을 보인 뒤에만.

## A1 설계 — 덱 글 병합
- 가져오기 끝(제어·DB)에서 새로 만든 객체마다 ① 덱 원문 줄 ② 가져온 직후의 표기 ③ 속성 사본을 붙인다. 대상은 한 벌짜리 제어 객체와 DB 객체(HISTORY·NODAL_FORCE_GROUP 은 여러 줄 개체라 뺀다).
- 쓸 때: 지금 표기와 가져온 직후 표기를 칸 단위로 견준다. 다르면 모드가 바꾼 칸 — 지금 표기. 같으면 지금 표기를 두되, 덱 칸이 비어 있지 않고 표기 칸이 비었거나 수치가 다르면 덱 글. 표기보다 많은 덱 칸·덱 줄은 그대로 붙인다.
- 모드가 객체를 새로 만들면(`SetControlX`·`SetDatabaseX`·`clear`) 덱 정보는 따라가지 않는다 — 그 카드는 모드가 통째로 다시 정한 것(지금과 같다).
- 안전장치: 표기에 안 보이는 속성 변화가 있으면 모델 부분은 지금 표기 그대로, 조건부 끝 카드(동적 이완 IDRFLG)는 그 값이 그대로일 때만, 긴 형식(`+`) 블록은 병합하지 않는다.
- 결과: 지금 출력이 수치로 충실한 곳은 바이트가 같다. 바뀌는 바이트는 모두 되살아난 값이다.
- 기록기의 실수 포맷(>10.3e 등)은 그대로 둔다 — 모드가 정한 값의 글이 바뀌지 않는다.
