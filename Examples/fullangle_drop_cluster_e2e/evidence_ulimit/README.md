# 증거 — `ulimit -v` 40 GB 가 후처리 피크를 낮게 만든다

`RESOURCES.md` 의 재현성 절이 주장하는 내용을 **클러스터·d3plot 없이** 다시 확인할 수 있게
원본 `result.json` 을 짝으로 떠 둔 것이다.

```bash
python3 verify_ulimit_finding.py
```

## 왜 이걸 남기는가

후처리(`koo_deep_report`)는 `ulimit -v` 가 요구량(최대 RSS 약 32.84 GiB)에 걸치면
**경고 없이 `rc=0` 으로 끝나면서 피크를 낮게 보고한다.** 로그가 경로만 빼고 바이트 동일해서
산출물을 비교하지 않으면 알 수 없다. 낮은 피크는 안전계수를 **과대평가**하므로
구조 판정에서 가장 위험한 방향이다.

주장의 근거가 실행 로그가 아니라 **산출물 자체**이므로, 산출물을 보존해야 검증이 성립한다.

## 교차 확인 — 최대 RSS 분포

같은 작업 20방향, `ulimit -v` 만 다르다.

| `ulimit -v` | 최소 | 중앙 | 최대 | 폭 |
|---|---|---|---|---|
| 40 GB | 32.556 GiB | 32.674 GiB | 32.766 GiB | 215 MiB |
| 60 GB | 32.838 GiB | 32.839 GiB | 32.840 GiB | **2 MiB** |

60 GB 에서 사실상 고정인 값이 이 작업의 자연 요구량이다. 40 GB 에서는 그보다 **적게** 쓰고,
얼마나 적은지가 실행마다 흔들린다 — 천장이 할당을 깎았다는 직접 증거다.

원 실험 디렉터리(전체 산출물 509 MB)는 클러스터에 남겨 뒀다.
